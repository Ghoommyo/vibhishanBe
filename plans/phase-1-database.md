# Phase 1: Schema, migrations, seed

## Goal
The normalized schema from spec §8 is in place, managed by Alembic, with the exact seed data from spec §9 and a dev reset endpoint.

## Steps
1. Add `app/db/models.py` with SQLAlchemy 2 typed models for `users`, `service_requests`, `request_participants`, `request_approvals`, `rooms`, `room_members`, `room_mutes`, `room_closures`, `room_ratings`, `messages`, `message_stars` and `notifications`. They include the CHECK constraints, the functional unique indexes on `lower(username)` and `lower(email)`, and the partial index on unread notifications.
2. Set up Alembic. `alembic/env.py` takes the URL from settings and `target_metadata` from the models. The initial revision is autogenerated, then reviewed.
3. Add `app/seed.py`. `seed(session, now)` inserts the users, 9 sessions (requests, approvals, rooms, members, messages, stars, closures, ratings) and 2 notifications, with timestamps relative to `now`. `reset(session)` truncates every table and re-seeds. It runs as `python -m app.seed`.
4. Add `app/routers/dev.py` with `POST /dev/reset` (returns 204). It is mounted only when `ENABLE_DEV_ENDPOINTS=true`.
5. Add `tests/conftest.py`, which runs migrations against `vibishan_test` once and re-seeds before each test.

## Tests
- The seed's row counts are right: 7 users, 9 rooms, 2 notifications, and so on.
- Session 8 is active and session 9 is pending with no messages.
- `POST /dev/reset` restores the seed after a modification.
